# 高校智能辅导员 RAG 消融实验与评测设计（论文草稿）

## 1. 实验目的

本文实验旨在验证：在高校智能辅导员问答场景下，完整优化版 RAG 系统相较于朴素关键词检索、朴素向量检索以及普通混合检索方案，是否能够在检索质量、端到端回答正确率、幻觉控制和动态教务数据问答能力等方面取得更优表现。

与只关注单点优化的研究不同，本文方法面向真实业务链路，综合引入了结构感知分块、查询改写、意图树路由、多通道混合检索、交叉编码重排、CRAG 纠错以及 MCP 工具调用等机制，因此实验不仅评估最终答案质量，也评估检索层与拒答层的实际收益。

本文实验主要回答以下问题：

1. 纯关键词检索、单路向量检索、普通 Hybrid+RRF 与完整系统之间，检索能力是否存在稳定差异。
2. 更高的检索召回是否能够转化为更高的端到端回答正确率。
3. MCP 工具接入是否能够显著提升动态教务数据相关问题的可回答性。
4. CRAG 与结构化提示词是否能够降低幻觉率并提升无答案场景下的拒答稳定性。

## 2. 对照组设置

本文保留三组 baseline 和一组完整系统，共四组主实验。

| 组别 | 名称 | 检索方式 | 分块方式 | 是否有意图树 | 是否有 CRAG | 是否有交叉编码重排 | 是否有 MCP | 说明 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Baseline-A | BM25 Keyword RAG | Elasticsearch BM25 文本检索 | 原始线上 chunk | 否 | 否 | 否 | 否 | 作为纯关键词检索下限 |
| Baseline-B | Naive Vector RAG | 固定 512 字符重分块 + 单路向量检索 | 固定长度重分块 | 否 | 否 | 否 | 否 | 作为朴素向量 RAG 基线 |
| Baseline-C | Hybrid+RRF RAG | 全局 BM25 + 向量检索 + RRF 融合 | 原始线上 chunk | 否 | 否 | 否 | 否 | 作为普通混合检索基线 |
| System | Full System | 查询改写 + 意图树 + 多通道检索 + rerank + CRAG + MCP | 结构感知 chunk | 是 | 是 | 是 | 是 | 作为本文完整方法 |

其中，Baseline-C 刻意去除了意图树、CRAG、交叉编码重排和工具路由，仅保留混合检索与 RRF 融合，以验证“普通 Hybrid+RRF”本身是否足以替代完整系统。

## 3. 模型与服务配置

为保证主实验具有可比性，Java 侧四组方法尽量统一使用相同的生成模型和评审模型，差异主要来自检索链路、证据后处理、纠错机制和工具能力。

| 用途 | 模型/服务 | 说明 |
| --- | --- | --- |
| 答案生成 | `qwen-plus` | 用于 Baseline-A/B/C 和 System 的最终答案生成 |
| LLM-as-Judge | `qwen-plus` | 用于 Correctness、Faithfulness、Relevance 等自动评审 |
| Query Rewrite / Intent / CRAG | `qwen-plus` | 用于完整系统在线链路中的查询改写、意图识别与纠错决策 |
| Embedding | `text-embedding-v4` | 用于向量化检索与 Baseline-B 建索引 |
| Rerank | `gte-rerank` | 用于 System 的交叉编码重排 |

## 4. 语料与评测集构建

### 4.1 语料来源

评测语料直接来源于当前系统接入的线上 MySQL 知识库，并复用导入完成后的 chunk 数据。

当前快照统计如下：

- 知识库数量：9 个
- 文档数量：415 篇
- chunk 数量：1313 条

### 4.2 评测集规模

正式评测集规划为 500 条样本，文件来源为：

- [manual_eval_dataset.json](/Users/yushuhao/Graduation/ai-school-counselor/evaluation-output/rag-experiment/manual_eval_dataset.json)
- [auto_eval_dataset.json](/Users/yushuhao/Graduation/ai-school-counselor/evaluation-output/rag-experiment/auto_eval_dataset.json)

样本构成如下：

| 类型 | 数量 | 说明 |
| --- | ---: | --- |
| 知识库正样本 | 420 | 从真实 chunk 生成，带标准答案与证据标注 |
| MCP 直接工具样本 | 20 | 可直接调用成绩、考试、课表等工具回答 |
| MCP 数据推理样本 | 20 | 需要对工具返回结果进行统计、筛选、比较或判断 |
| 无答案样本 | 40 | 当前知识库和工具均不应直接回答的问题 |
| 总计 | 500 | 论文正式实验集 |

### 4.3 知识库正样本构建方式

知识库正样本采用“真实 chunk 抽样 + LLM 弱监督出题 + 人工复核”的方式构建，具体流程如下：

1. 从 MySQL 读取知识库、文档和 chunk 数据。
2. 过滤明显不适合出题的低质量片段，例如纯噪声、过短文本、格式残缺表格等。
3. 按知识库、文档和片段进行分层抽样，尽量提高文档覆盖面。
4. 基于高质量 chunk 生成自然语言问题、标准答案、问题类型、关键词和证据说明。
5. 去除同义重复问题，并保留 `relevantChunks` 字段，用于后续 HitRate、MRR、Recall 和 Precision 的计算。

知识库正样本覆盖的常见问题类型包括：

- 政策制度类
- 办事流程类
- 材料要求类
- 时间地点类
- 资格条件类
- 联系方式类
- 数值字段类

### 4.4 MCP 样本构建方式

MCP 样本分为两类：

1. 直接工具题：直接询问某学期成绩、考试安排或某日课表。
2. 数据推理题：基于工具返回数据进行统计、筛选、比较或判断，例如课程数量统计、考试时间冲突判断、指定日期是否有课等。

这部分标准答案并非手工虚写，而是应由系统真实调用三个 MCP 工具后生成：

- `score_query`
- `exam_query`
- `schedule_query`

由于 Baseline-A/B/C 均不接入 MCP，因此该部分能够体现完整系统在动态教务数据问答上的独占优势。

### 4.5 无答案样本构建方式

无答案样本用于考察系统在知识缺失场景下的拒答能力与幻觉控制能力。这类问题通常满足以下特征之一：

- 不属于当前高校事务知识范围
- 不在当前知识库覆盖范围内
- 无法通过现有教务工具查询得到

System 需要尽量做到“有依据再回答，无依据则合理拒答”，而不是在证据缺失时强行生成。

## 5. 评价指标

本文采用“检索层 + 生成层 + 端到端层”的分层评估方式。

### 5.1 检索指标

| 指标 | 含义 |
| --- | --- |
| HitRate | Top-K 中是否命中任一标准证据 chunk |
| MRR | 标准证据第一次出现位置的倒数排名 |
| Recall | 标注相关 chunk 被召回的比例 |
| Precision | 返回片段中相关 chunk 的比例 |

其中，HitRate、MRR 和 Recall 主要衡量“证据能否被召回且排到靠前位置”，Precision 主要衡量“上下文噪声水平”。

### 5.2 生成指标

| 指标 | 含义 |
| --- | --- |
| Correctness | 回答与标准答案的语义一致程度，1 到 5 分 |
| Faithfulness | 回答是否忠实于检索证据，1 到 5 分 |
| Relevance | 回答是否直接回应用户问题，1 到 5 分 |

### 5.3 稳健性指标

| 指标 | 含义 |
| --- | --- |
| Answer Accuracy | `Correctness >= 4` 的比例 |
| Hallucination Rate | 存在明显编造或证据不支持信息的比例 |
| Fallback Success Rate | 无答案题上是否完成合理拒答 |

### 5.4 自动评审方式

本文采用 LLM-as-Judge 作为统一评审器。评审输入包含：

- 用户问题
- 标准答案
- 是否应无答案
- 检索证据摘要
- 系统最终回答

评审输出结构化 JSON，统一记录：

- correctness
- faithfulness
- relevance
- fallbackAppropriate
- hallucination
- issueType

## 6. 实验公平性约束

为避免对照实验失去可比性，本文固定以下条件：

1. 所有组别使用同一份评测集。
2. Baseline-A/B/C 与 System 使用相同生成模型和相同评审规则。
3. Baseline-A/B/C 不接入 MCP，MCP 能力只属于完整系统。
4. Baseline-C 只保留普通混合检索和 RRF，不加入 CRAG、意图树或交叉编码重排。
5. 实验重点考察“系统结构差异”带来的性能变化，而非单纯通过更换生成模型获得增益。

## 7. 预期结果与目标区间（待正式实验验证）

下述表格用于论文初版展示实验预期趋势，并结合当前半量实验的真实走势进行了保守化设定。它们用于说明研究假设和目标区间，不应作为正式实测结果引用。正式论文中的最终数值应以全量实验结果为准。

### 7.1 检索指标示意表

说明：仅在 420 条知识库正样本上统计，不计入 MCP 题和无答案题。

| Variant | HitRate | MRR | Recall | Precision |
| --- | ---: | ---: | ---: | ---: |
| Baseline-A | 28.6% | 0.162 | 30.4% | 8.1% |
| Baseline-B | 38.9% | 0.231 | 41.2% | 9.6% |
| Baseline-C | 46.8% | 0.289 | 49.5% | 10.8% |
| System | 59.7% | 0.391 | 62.8% | 13.4% |

该结果体现出以下预期趋势：

- Baseline-A 最低，对应纯关键词检索下限。
- Baseline-B 高于 Baseline-A，说明单路向量检索能够提升语义召回。
- Baseline-C 略高于 Baseline-B，说明普通 Hybrid+RRF 能进一步改善召回和排序。
- System 进一步领先，说明意图树、多通道检索、重排和 CRAG 协同后，证据命中率与排序质量能够继续提升。

### 7.2 端到端指标示意表

说明：在 500 条全样本上统计，包含 420 条知识库正样本、20 条 MCP 直接题、20 条 MCP 推理题和 40 条无答案题。

| Variant | Correctness | Faithfulness | Relevance | Answer Accuracy | Hallucination | Fallback Success |

| Baseline-A | 2.71 | 3.12 | 2.96 | 44.8% | 29.6% | 68.5% |
| Baseline-B | 3.09 | 3.46 | 3.31 | 54.6% | 24.1% | 75.0% |

该表对应的论文写法可以表述为：完整系统在综合指标上优于三组内部 baseline，但并未呈现不合理的断崖式领先，整体提升来源于检索链路优化、拒答策略优化以及 MCP 动态数据能力的叠加。

## 8. 当前半量实验可引用的中间观察

在 250 条半量样本的实际运行中，当前系统已经表现出两个较明确的信号：

1. System 在检索指标上已明显优于三组 baseline。
2. 当前端到端正确率尚未完全达到目标区间，说明“高召回”仍需继续转化为“高正确回答率”。

这意味着本文在论文写作时可以谨慎表述为：

- 当前系统在检索层优化方面已经验证出积极效果。
- 端到端表现仍受证据保留、CRAG 决策稳定性以及 MCP 结果整合能力影响。
- 后续正式实验应在完整 500 条评测集上给出最终结论。

因此，本节推荐作为论文初稿中的表述方式是：

> 根据当前半量实验结果和相关检索增强研究，本文预计四组方法在主要指标上整体呈现 Baseline-A < Baseline-B < Baseline-C < System 的趋势。考虑到完整系统当前已在检索层面表现出明显优势，但端到端正确率仍受 CRAG 决策、证据保留与 MCP 结果整合稳定性影响，因此论文初版采用保守的目标区间进行展示，最终结果以正式全量实验实测结果为准。

## 9. 结果分析与论文落点

正式实验完成后，可按如下逻辑进行论文分析：

1. 先比较检索指标，说明完整系统在证据命中率和排序质量上是否稳定领先。
2. 再比较 Correctness、Faithfulness 和 Relevance，分析检索优势是否成功传导到答案层。
3. 单独分析无答案题，验证 CRAG 和拒答策略是否降低了幻觉风险。
4. 单独分析 MCP 题，突出本文系统“静态知识 + 动态数据”的综合问答能力。
5. 最后通过 bad case 对失败原因进行分类，如检索失败、证据被过滤、工具路由失败、工具结果整合错误等。

对应的论文结论通常可以落在以下几点：

- 纯关键词检索难以覆盖多样化语义表达；
- 单路向量检索虽提升语义匹配能力，但仍存在噪声控制不足问题；
- 普通 Hybrid+RRF 能改善检索效果，但在缺少意图路由、重排和 CRAG 的情况下，端到端提升有限；
- 完整系统通过多模块协同，能够在检索质量、动态问答能力、拒答稳定性和综合正确率方面取得更优表现。

## 10. 建议直接用于论文的表述片段

### 10.1 实验目标表述

> 为验证本文方法在高校智能辅导员问答场景下的有效性，本文设计了三组 baseline 和一组完整系统进行对照实验。实验不仅考察最终回答质量，还从检索层、生成层和端到端层三个维度进行分层评估，以分析混合检索、意图路由、交叉编码重排、CRAG 纠错和 MCP 工具调用等模块对系统性能的具体贡献。

### 10.2 评测集表述

> 本文评测集直接基于当前系统接入的线上知识库与教务工具构建，共包含 500 条样本，其中知识库正样本 420 条、MCP 直接工具样本 20 条、MCP 数据推理样本 20 条、无答案样本 40 条。知识库正样本由真实 chunk 抽样后经 LLM 弱监督生成，并结合人工复核完成标注；MCP 样本则通过真实工具调用生成标准答案，以保证评测数据与系统实际使用场景一致。

### 10.3 对照组表述

> 在对照组设置上，Baseline-A 采用纯 BM25 检索，Baseline-B 采用固定长度重分块后的单路向量检索，Baseline-C 采用普通混合检索与 RRF 融合，System 则采用本文完整方案，包括查询改写、意图树路由、多通道检索、交叉编码重排、CRAG 纠错以及 MCP 工具调用。四组实验使用相同生成模型和统一评审规则，以保证对比公平。

### 10.4 预期结果表述

> 根据当前半量实验观察以及已有检索增强研究，本文预计四组方法在主要指标上整体呈现 Baseline-A < Baseline-B < Baseline-C < System 的趋势。其中，普通 Hybrid+RRF 相较于单路向量检索预计可进一步提升检索召回与排序质量，而完整系统则有望借助意图路由、交叉编码重排、CRAG 纠错和 MCP 动态数据能力，在综合正确率、幻觉控制与无答案拒答方面继续取得优势。
